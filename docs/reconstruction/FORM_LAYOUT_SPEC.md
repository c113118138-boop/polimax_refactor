## 重複列的四種狀態

1. 空資料：顯示「尚無資料，請新增一筆」及左下新增鈕；不自動加入空白保存列。
2. 新增／編輯：在本表格下方、增加鈕原位置展開白色編輯區，1px框、16px內距（手機12px）；按下方順序垂直排列欄位；底部左側保存、取消。
3. 保存摘要：標籤列#f8f9fa、字重600；資料／標籤格10px 12px，靠左靠上、底框1px；操作在最後一欄，編輯和刪除並列。空值顯示破折號；時間以臺北時區顯示。
4. 驗證失敗：不提交資料列；取消新增不加入列，取消既有編輯回復原列。未保存列存在時禁止整表提交及切換用途。刪除明細使相應時段對應失效，要求重新選明細，避免暗中挪到其他案件。

明細摘要最小720px。欄位依下列表左右排列，操作最後；各欄保留可讀寬度。時段摘要以類別／資源／開始／結束／操作的 **2:2:3:3:2** 比例排列，即16.667%、16.667%、25%、25%、16.666%，最小720px；A每筆时段前重複表頭，E使用表頂標籤。這個比例在 A 模板可確認；E 沿用本案正常時段操作，正式頁最終寬度列U。

列保存只改本地表單；整表送出才呼叫預約 API。不得把「取消列」「刪除本地列」「删除伺服器申請」視為同一件事。

## A 車輛使用需求單

同頁由上至下：預約基本資訊 → 車輛借用用途及細項 → 車輛借用資訊 → 需求選項清單 → 補充資訊 → 送出。沒有介紹、步驟条、右側預約摘要。

**預約基本資訊**：申請日期唯讀全寬；申請人唯讀全寬。依使用者修正，不顯示來源沒有的「申請緣由」。API／查詢所需title在送出時自動使用既有使用需求；修改舊單保留已保存title，不增加輸入欄或額外必填項目。

**用途及細項**：總使用人數 → 使用需求單選 → 該需求明細。編輯與保存摘要的欄順如下（各列最後另有操作）：

| 需求 | 欄位左右順序／編輯時上下順序 |
| --- | --- |
| 工案 | 工案編號、縣市、行政區、工程組長、工案業務 |
| 材料送貨 | 縣市、行政區、業主名稱、送貨業務 |
| 新開發案 | 開發案編號與名稱、縣市、行政區、新開發案業務 |
| 客戶拜訪 | 縣市、行政區、客戶名稱 |
| 成交案回訪 | 工案編號、縣市、行政區、工程組長、工案業務 |
| 參展 | 縣市、行政區、展覽名稱 |
| 其他 | 縣市、行政區、備註 |

縣市必填；名稱除材料送貨外必填；行政區依縣市選項刷新，改縣市清空舊區域。人員使用現行手動輸入：第一位業務帶入登入者，第二位可填，組長可填文字。新開發案不額外插入來源沒有的組長。

需求切換在原位置更換明細與時段。保留現行 `reason_drafts` 以便切回恢复；只驗證與建立目前類別的預約索引。這是既有正常功能相容R；來源隱藏清空宣告另有差異。

**借用資訊**：使用人員在上（第一位唯讀、第二位可手填，兩欄上下排列），之後時段表。編輯欄序：類別／對應明細 → 車輛 → 借用開始 → 借用結束。日曆選取的車輛和時間作為新增時段初值，含秒與臺北時區。A一明細可對應多時段；多明細須與時段一對一。衝突與相接邊界按既有後端檢查。

**需求清單**：四列五欄、每格20%、最小750px；保持表格，不拆卡。

## D 作業區／工具間

唯一panel「申請資料」：申請人 → 開始時間 → 結束時間 → 樓層地點 → 1F區域 → 該區編號 → 2F辦公區。所有欄全寬，核取選項逐項上下排列；没有A的用途、明細或額外wizard。

樓層、區域可複選；關閉樓層／區域會移除其資源時段；只選區域、尚未選所需編號不能送出。各已選資源共用頂部時間，编辑帶回各區域與編號。既有不同時間的D資料初次載入保留各slot；使用者改頂部時間才同步。

1F區域來源順序：批覆區、拆組裝區、裝載區、汞浦試壓區、噴砂室、研磨與氣動除鏽區、產品說明室。編號條件位置按拆組裝、批覆、研磨；選項由現行`/resources`的floor/area/unit回填。2F有會議室、會客室。資料沒有floor的歷史區域列「其他」，可辨識而不捏造樓層。

## 保存、權限與尚未確認

沿用`POST/PUT /api/bookings`、`POST /bookings/:id/advance`、`PUT /stages/:id`、`POST/GET /files`與既有revision／owner檢查。A修改產生新ID並連前版，D/E修改保留ID；B/C修訂不倒退流程。舊JSON的A組長／業務、成交案回訪名稱、用途與其它說明補齊編解碼；E保留既有`_polimax_next.content`契約。`detail_index`須有效，不接受負值指向其他明細。
